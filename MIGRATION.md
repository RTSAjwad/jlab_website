# JLab Site Migration — Status & Notes

This document records the current state of the migration of
<https://www.japanese-like-a-breeze.com/> to an Astro + Starlight site, along
with the assumptions, disclaimers, and remaining work.

> **Scope note:** this migration was performed purely from the *publicly
> accessible* pages of the original WordPress site. We do not have access to the
> original source code, theme, templates, or any unpublished content. Where the
> live pages could not be queried programmatically (e.g. the exact `href` of
> every link), some targets had to be inferred and later corrected.

---

## 1. What was built

- **Stack:** Astro 7 (bleeding-edge, per the `create astro` scaffold) +
  Starlight 0.42 + the `starlight-blog` plugin (`v0.29.0`).
- **Package manager:** pnpm, provided by a Nix flake dev shell (`nodejs_24` +
  `pnpm`).
- **Search:** Starlight's built-in Pagefind search (generated automatically at
  build time).
- **Sitemap:** generated automatically by Astro.
- **RSS:** generated by `starlight-blog` for the `/blog/` section.


The original site's "Choose your Level" prompt and top-level navigation are

### Social links

Only the social channels that actually exist on the original site are exposed:

- **Patreon** → <https://www.patreon.com/jlabjapanese>
- **Email** → <mailto:japaneselikeabreeze@gmail.com>

> **Correction history:** the original author's Patreon handle is
> `jlabjapanese` (not `japanese_like_a_breeze` as initially guessed). A
> fabricated GitHub link and fabricated YouTube channel URL were removed — the
> original site has no GitHub presence and no YouTube *channel* link (only
> individual video links inside content).

### Site URL / `base` / RSS

- `base` is set to `/jlab_website` (the GitHub project repository), so all
  absolute paths are prefixed accordingly.
- `site` defaults to the GitHub project URL `https://RTSAjwad.github.io` (the
  production target). During local development, the Nix dev shell exports
  `SITE_URL=http://localhost:4321`, and the config reads
  `process.env.SITE_URL ?? <production>`. See `README.md` and `flake.nix`.
- Deployment is handled by `.github/workflows/deploy.yml` (the official
  `withastro/action` → `actions/deploy-pages`). The GitHub repository must be
  set to use **GitHub Actions** as the Pages source.

## 5. Content changes & editorial decisions

The migration is faithful in *content* but involved the following deliberate
changes:

1. **WordPress chrome removed.** The repeating footer ("Copyright, all rights
   reserved", "Blue sky image courtesy of Constance Chen", the sliding-bar
   contact widget, "Choose your Level", "Go to Top", and share/comment
   scaffolding) is WordPress theme chrome, not content, and was dropped. Starlight
   provides equivalent navigation and theme features.

2. **Comments not migrated.** Blog comments from the WordPress posts were not
   ported (e.g. the comment threads on "a-million-flashcards",
   "videomining", "dont-learn-kanji-readings"). They are recoverable from the
   source if needed.

3. **Blog posts without a dedicated page.** Blog posts that duplicate a guide or
   reference page (e.g. "delete-flashcards", "how-to-continue",
   "how-to-practice-speaking", "google-for-japanese-grammar", "addon-changes")
   are implemented as short blog entries that link to the full page, to avoid
   maintaining two copies of the same long-form content.

4. **Inline images/audio embedded.** The FAQ card screenshots, the
   googling-grammar audio + stills, the card-customization screenshots, and the
   troubleshooting screenshots were rehosted to `public/assets/` and embedded.
   See §7 for the file inventory.

5. **Spelling.** The original text frequently used *"roumaji"* (a non-standard
   spelling of *rōmaji*/*romaji*). This was preserved verbatim rather than
   silently "correcting" the author's voice. Flag if a global correction is
   desired.

6. **Dead internal links.** Several original pages referenced targets that do
   not exist as WordPress pages (e.g. "Troubleshooting guide", "Other decks",
   "read more here", "Get it here"). These were mapped to the nearest equivalent
   page in the new structure where a target could be identified, or linked to
   the /contact/ or /decks/ page. There may be residual placeholders to review.

7. **External deck/video links.** Ankiweb deck IDs, YouTube video IDs, Patreon
   URLs, and the Mediafire/Jisho/Blogspot references were preserved from the
   source where discoverable.

## 6. Known caveats & disclaimers

- **No source access.** Everything is reconstructed from live fetched pages.
  Some decisions (splitting guides, blog post short/long split, taxonomy
  omission) are editorial judgments, not the original author's.

- **Astro 7 / `starlight-blog` type mismatch.** Astro 7.3 bundles a newer Zod
  than `starlight-blog` v0.29 is typed against. This produces spurious
  *type-only* errors (visibile in the editor / `astro check`), but **does not
  affect** `astro build` / `astro dev`. Two files carry `@ts-nocheck` suppressions
  (`astro.config.mjs`, `src/content.config.ts`) with explanatory comments. A
  future `starlight-blog` release (or a stable Astro 7-compatible build) should
  remove the need for these. A related `@astrojs/markdown-satteri` peer
  dependency warning appears in `pnpm` output but is harmless at runtime.

- **Images were re-encoded by extension.** Some `.jpg` images were initially
  saved with `.png` names based on misguessed extensions, then renamed to `.jpg`
  after `file` inspection confirmed them as JPEG. Content-type is now correct.

- **External Google-hosted images not localized.** Four `lh3.googleusercontent.com`
  screenshots on the addon-manual page were not downloaded (external host, not
  in the WordPress uploads). They remain as placeholders only if referenced.

- **`.env` is not read by `astro.config.mjs` in Astro 7.** `process.env` in the
  config only picks up variables set in the *shell* (not `.env` files). Hence
  the `SITE_URL` value is wired through the Nix `shellHook` rather than `.env`.
  This is non-obvious and worth keeping in mind for CI/deploy.
